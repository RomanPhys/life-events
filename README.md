# Прогноз покупки банковских продуктов по транзакциям

Пет-проект на открытом датасете MBD от Sber AI Lab ([Mollaev et al., 2024](https://arxiv.org/abs/2409.17587)). По истории транзакций клиента нужно предсказать, возьмёт ли он в следующем месяце каждый из четырёх банковских продуктов. Покупки редкие, от 0.05% до 0.3% клиенто-месяцев.

Я сравнил LightGBM на агрегатах, GRU и трансформер, обученный с нуля и после self-supervised предобучения (masked event modeling). Так как позитивов мало, разница в сотые доли ROC-AUC легко оказывается шумом, поэтому модели сравниваю парным бутстрэпом по клиентам на одном тесте.

## Результаты коротко

| Модель | ROC-AUC, 4 продукта | ROC-AUC, 3 продукта с ≥100 позитивами |
|---|---|---|
| LightGBM, 137 агрегатов | 0.791 | 0.790 |
| GRU (3 сида) | 0.802 ± 0.009 | 0.779 ± 0.005 |
| Трансформер с нуля (3 сида) | 0.791 ± 0.007 | 0.778 ± 0.003 |
| Трансформер + MLM (3 сида) | 0.802 ± 0.003 | 0.788 ± 0.002 |

1. Нейросети не обошли бустинг. По четырём продуктам они выше на 0.015-0.024, но весь выигрыш даёт один продукт, у которого в тесте около 25 позитивов. На остальных трёх разница от -0.003 до +0.001, и 95% доверительный интервал везде включает ноль.
2. Предобучение уменьшило разброс между сидами в 3 раза (std 0.0070 против 0.0025) и подняло одиночную модель на 0.011. При этом ансамбль из трёх сидов без предобучения работает так же (разница +0.0002, CI от -0.011 до +0.010). Получается, что предобучение здесь в основном снижает дисперсию.
3. Когда размечено только 5% клиентов, предобучение даёт +0.035 ROC-AUC (CI от -0.001 до +0.074), на границе значимости. При 20% и 100% разметки эффекта нет.
4. Эмбеддинги из предобученного энкодера как признаки не работают: 0.70 в бустинге сами по себе, а вместе с агрегатами качество падает на 0.011.
5. Если модели показать события целевого месяца, ROC-AUC растёт на 0.025. Поэтому отсечку я проверяю отдельно (см. ниже про часовой пояс).

## Данные

Использую MBD-mini ([ai-lab/MBD-mini](https://huggingface.co/datasets/ai-lab/MBD-mini), CC-BY-4.0). В транзакциях есть тип, подтип, валюта, анонимизированные признаки отправителя и получателя, сумма и время. Метки помесячные, по четырём продуктам.

Чтобы уместиться в память Colab, беру 40 тыс. клиентов (выбор детерминированный, по хешу id) и последние 6 месяцев каждого. Это 15.9 млн транзакций и 230 тыс. клиенто-месяцев.

Разбиение по фолдам авторов: фолд 0 тест (46 375 клиенто-месяцев), фолд 1 валидация, остальные обучение. Один клиент не может попасть в разные части. Предобучение идёт только на клиентах из обучения.

В тесте доля позитивов по продуктам 0.23%, 0.05%, 0.30% и 0.23%, то есть примерно 110, 25, 140 и 110 позитивов. На 25 позитивах ROC-AUC слишком шумная, поэтому кроме средней по всем продуктам считаю среднюю по трём остальным.

Для месяца M модель видит только события до начала M, как в статье. Это проверяют тесты.

## Модели

- LightGBM на 137 признаках: статистики всей истории и последних 256 событий, активность за 7, 30 и 90 дней, тренд, доли частых значений каждого категориального поля. Отдельная модель на каждый продукт.
- GRU с hidden 256 поверх эмбеддингов событий, по последнему состоянию. Это аналог Supervised RNN из статьи MBD.
- Трансформер: 4 слоя pre-LN encoder, d=128, 4 головы, классификация по CLS. Позиции считаются от последнего события, чтобы при разной длине истории свежесть события кодировалась одинаково.
- MLM-предобучение: 6000 шагов, маскирую 15% событий и восстанавливаю их категориальные поля и корзину суммы.

Эмбеддинг события собирается из эмбеддингов 11 категориальных полей, дня недели, нормированной суммы, log времени с предыдущего события и log времени до отсечки. На вход идут последние 256 событий. Обучение: AdamW, warmup и cosine, AMP, early stopping по валидации.

GRU тут не формальный бейзлайн. В бенчмарке EBES ([Osin et al., 2024](https://arxiv.org/abs/2410.03399)) лучшими на последовательностях событий оказались как раз GRU с предобучением, а в статье MBD supervised RNN обходит CoLES и TabBERT.

## Все результаты

Метрики считаю по каждому продукту и усредняю. Для нейросетей указано среднее ± std по сидам.

| Конфигурация | Сидов | ROC-AUC, 4 | ROC-AUC, 3 | PR-AUC |
|---|---|---|---|---|
| LightGBM | 1 | 0.7905 | 0.7904 | 0.0113 |
| GRU | 3 | 0.8024 ± 0.0094 | 0.7789 ± 0.0047 | 0.0122 ± 0.0003 |
| Трансформер с нуля | 3 | 0.7913 ± 0.0070 | 0.7780 ± 0.0031 | 0.0157 ± 0.0019 |
| Трансформер + MLM | 3 | 0.8024 ± 0.0025 | 0.7884 ± 0.0017 | 0.0166 ± 0.0025 |
| LightGBM, агрегаты + MLM-эмбеддинги | 1 | 0.7869 | 0.7793 | 0.0161 |
| LightGBM, только MLM-эмбеддинги | 1 | 0.7004 | 0.6913 | 0.0083 |
| LightGBM с событиями целевого месяца (проба утечки) | 1 | 0.8159 | 0.8102 | 0.0187 |

Для сравнения, в статье MBD на полном датасете у агрегатов 0.783, у CoLES 0.773, у TabGPT 0.802, у Supervised RNN 0.819. Мой LightGBM получил тот же уровень, что агрегаты в статье. Напрямую цифры сравнивать нельзя, у меня подвыборка и одно разбиение вместо 5-fold.

По PR-AUC трансформеры выше бустинга (0.0166 против 0.0113, это примерно в 8 и в 5.6 раза выше доли позитивов). Парного теста для PR-AUC я не делал, так что это пока наблюдение.

### Мало разметки

ROC-AUC по трём продуктам. Доля считается от клиентов обучающей выборки.

| Разметка | С нуля | С MLM | Разница ансамблей | 95% CI |
|---|---|---|---|---|
| 100%, 3 сида | 0.778 ± 0.003 | 0.788 ± 0.002 | 0.000 | [-0.011; +0.010] |
| 20%, 2 сида | 0.718 ± 0.018 | 0.730 ± 0.012 | +0.003 | [-0.014; +0.019] |
| 5%, 2 сида | 0.557 ± 0.003 | 0.574 ± 0.027 | +0.035 | [-0.001; +0.074] |

При 5% в обучении остаётся около 20 позитивов на продукт (у самого редкого единицы), и обе модели почти случайные. Намёк на пользу предобучения есть, но для вывода нужно больше сидов.

### Часовой пояс

Транзакции в данных начинаются 2020-12-31 в 21:00:04 и заканчиваются 2022-12-31 в 20:59:56. Это московская полночь, записанная в UTC. Месяцы меток календарные, значит без поправки в историю попадают первые три часа целевого месяца.

Я заметил это уже после основных экспериментов и перезапустил LightGBM со сдвигом времени на 3 часа:

| | Разница, 4 продукта | 95% CI | Разница, 3 продукта | 95% CI |
|---|---|---|---|---|
| LightGBM со сдвигом минус без сдвига | -0.005 | [-0.020; +0.009] | -0.009 | [-0.019; +0.001] |

Эффект на границе значимости. Все модели учились на одинаковых данных, так что сравнения между ними корректны, но абсолютные значения могут быть завышены примерно на 0.005-0.01. Поправка включается флагом `--time-shift-hours 3` в `src/prepare.py`, пересчёт основных моделей с ней в планах.

## Выводы

На подвыборке MBD, где на продукт приходится около сотни позитивов в тесте, последовательные модели не дают значимого выигрыша над хорошими агрегатами. В статье на полном датасете GRU опережает агрегаты на 0.036, так что, вероятно, нейросетям просто не хватает данных. Это гипотеза, на подвыборке я её не проверял.

MLM-предобучение здесь полезно как способ стабилизировать обучение и, возможно, при малой разметке. Готовые эмбеддинги клиента оно не даёт. Скорее всего, восстановление отдельных событий учит модель локальным деталям транзакций, а не тому, что за клиент перед ней. Для эмбеддингов логичнее пробовать контрастивное предобучение вроде CoLES.

И главное, что я вынес: по одиночным запускам и средней по четырём продуктам нейросети выглядят лучше бустинга на 0.011-0.024, а предобучение лучше обучения с нуля на 0.011. Без парных сравнений я бы сделал неверные выводы.

## Синтетика

Перед реальными данными я гонял всё на синтетике в той же схеме (`src/synthetic.py`, 3000 клиентов, один сид). В target_2 сигнал есть только в порядке событий: тип 7, а через 0-2 дня тип 8. Сами эти типы встречаются у всех клиентов. Так можно проверить, используют ли последовательные модели порядок, а не только частоты.

На этом таргете GRU даёт ROC-AUC 0.70 против 0.67 у LightGBM, то есть порядок она, похоже, ловит. Трансформер за 8 эпох на таком объёме его не выучил (0.63). Бустинг тоже что-то находит, видимо потому, что вставленные пары немного повышают частоту типов 7 и 8 перед целевым месяцем. Это проверка пайплайна на одном сиде, серьёзных выводов по ней делать нельзя. Таблица лежит в `reports/synthetic.md`.

## Как запустить

Все шаги есть в `notebooks/run_experiments.ipynb`, в Colab с GPU это около 3 часов. Ноутбук лежит без выводов, все числа из прогона сохранены в `reports/`. Локально:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -t .          # 17 тестов, для 5 из них нужен torch
python -m src.inspect_mbd --download --root data/mbd
python -m src.prepare --raw data/mbd --out prepared/mbd --max-clients 40000 --last-months 6   # как для чисел выше; --time-shift-hours 3 включает поправку на часовой пояс
python -m src.gbm --data prepared/mbd --name gbm
python -m src.train pretrain --data prepared/mbd --name mlm --steps 6000
python -m src.train finetune --data prepared/mbd --model transformer --init runs/mlm/encoder.pt --lr 1e-4 --name tr_mlm_s0
python -m src.report
python -m src.report --compare "runs/tr_scratch_s*" "runs/tr_mlm_s*" --data prepared/mbd
```

Таблицы и сравнения из этого README лежат в `reports/` (`results.md`, `compare.txt`, `timezone_check.txt`).

## Ограничения и планы

- Пересчитать основные модели со сдвигом часового пояса.
- Взять больше данных: все 12 месяцев и больше клиентов. Пока разницы меньше примерно 0.02 ROC-AUC не различить.
- Сидов мало (1-3), разбиение одно, гиперпараметры подобраны вручную.
- Попробовать другие цели предобучения: контрастивную CoLES ([Babaev et al., 2022](https://arxiv.org/abs/2002.08232)), которая как раз рассчитана на эмбеддинги клиента, и предсказание следующего события (в статье MBD лучшим self-supervised вариантом был TabGPT).
- Диффузионные модели для событий, например Add-Thin ([Lüdke et al., NeurIPS 2023](https://arxiv.org/abs/2311.01139)) и Interacting Diffusion Processes ([Zeng et al., ICML 2024](https://proceedings.mlr.press/v235/zeng24f.html)). Они генерируют будущую последовательность целиком, и интересно, поможет ли это прогнозу редких покупок.
- Добавить другие модальности: в MBD есть геоданные и эмбеддинги диалогов.
